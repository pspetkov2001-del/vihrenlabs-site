# SURFACES.md — vihrenlabs.com rendering-surface registry

*Per the portfolio rule (Personal OS/CLAUDE.md → "Cross-surface validation"): when you change a brand token, copy string, layout, or nav, **walk this list** — don't trust that one page covers it. Created 2026-05-31 after a mobile-nav overlap bug slipped through because no registry existed.*

## Chrome (every page)
| Surface | File | Mobile behaviour to verify |
|---|---|---|
| Header / nav | `src/components/Nav.astro` | Desktop inline nav `hidden sm:flex`; **mobile hamburger** (`<sm`) toggles `#mobile-menu`. Test <640px: no overlap, menu opens/closes, active link highlights. |
| Footer | `src/components/Footer.astro` | `flex-col sm:flex-row` + `flex-wrap` on links — must stack/wrap on phone. |
| Base layout | `src/layouts/Base.astro` | `<head>` meta/OG tags, fonts, canonical, viewport. Wraps every page. |
| Structured data | `src/components/Schema.astro` | JSON-LD (Organization / Person / Product / Article). Validate via Google Rich Results after copy/price changes. |

## Brand tokens (the site's actual palette — verify everywhere on change)
- Background: `#080E14` (dark navy). Accent / CTA: `#E67E22` (orange), hover `#CA6F1E`.
- Text: white with opacity steps (`text-white`, `text-white/50`, `text-white/30`).
- Breakpoint: Tailwind `sm` = 640px is the mobile→desktop nav switch.
- *Note: the brand doc (`Spreadsheet OS Collection/docs/BRAND-ENTERPRISE-IT-OPERATOR.md`) specifies navy `#1E3D59`; the live site uses `#080E14` as the page background. Reconcile intentionally — don't "fix" one to the other without a decision.*

## How to use
On any token / copy / layout / nav change: edit, then walk this table and verify each affected surface — especially **render at <640px width** (the class of bug this registry exists to catch). Build (`npm run build`) and grep `dist/` for the changed marker before declaring done.
