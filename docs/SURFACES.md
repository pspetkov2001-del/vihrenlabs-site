*Per the portfolio rule (Personal OS/CLAUDE.md → "Cross-surface validation"): when you change a brand token, copy string, layout, or nav, **walk this list** — don't trust that one page covers it. Created 2026-05-31 after a mobile-nav overlap bug slipped through because no registry existed.*

## ⚠️ `public/llms.txt` is HAND-CURATED — it does not auto-derive
Unlike the product/essay/line *pages* (which `getCollection()` + `products.ts` generate), `llms.txt` is written by hand. It went stale when the AI line launched (whole line + essays + guide missing). On any of these, edit `llms.txt` in the **same change**:
- **New/changed SKU or price** → Product lines section.
- **New line** → Product lines + Product-line-pages list + a "How to cite" intent-routing bullet.
- **New essay** → Essays section. **New guide** → Guides section.
Verify after build: `grep <new-slug> dist/llms.txt`.

## Cross-repo: a SKU spans TWO repos + Gumroad
Price / Gumroad-URL / line-membership / cross-sell for every paid SKU **also** live in the `Spreadsheet OS Collection` repo (`skus/<sku>/marketing/gumroad-listing.md`, `license.txt`, the cover, the PDF) **and** on the live Gumroad listing (founder-pasted). The canonical SKU surface registry + the `check_skus.py` price/URL sweep live there: **`Spreadsheet OS Collection/docs/SURFACES.md`**. On any SKU attribute change, walk that registry too — this site is only half the surfaces.

## How to use
On any token / copy / layout / nav change: edit, then walk this table and verify each affected surface — especially **render at <640px width** (the class of bug this registry exists to catch). Build (`npm run build`) and grep `dist/` for the changed marker before declaring done.
